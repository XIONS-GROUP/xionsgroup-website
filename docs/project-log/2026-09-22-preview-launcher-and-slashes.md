# 2026-09-22 · 自助启动预览，并统一全站尾斜杠

承接[同日节奏与动效记录](2026-09-22-homepage-rhythm-and-motion.md)。

## 用户需求

用户指出：助手不工作时就打不开本地预览，这是个 bug；理想状态是助手把工具搭好，用户自己就能细调。要求先修这个，并说清楚到底要先运行什么、在哪里能找到。

## 问题根因

本地预览是一个真实的 HTTP 服务，必须有进程在跑。此前三次启动方式都把它的生命周期绑在了助手会话上：

1. 最早直接在助手的 Bash 调用里后台启动——进程留在该调用的进程组里，会话拆除时整组收到信号。
2. 后来改用用户终端面板的标签页——比前者好，但那个面板仍属于当前会话。

两种方式用户都无法在助手离场后自行恢复，而且**没有任何一个用户能自己找到并运行的入口**。

## 实施结果

### 自助启动入口

仓库根目录新增 **`启动本地预览.command`**（已 `chmod +x`）。macOS 下双击即用「终端」打开并运行：

- 先检测 4323 端口。已在运行就直接开浏览器并退出，不会重复启动。
- `node_modules` 不存在时自动 `npm ci`。
- 启动 `astro dev`，然后**轮询到服务真正能响应**才打开工具箱——直接 `open` 会因为服务未就绪而显示连接错误。
- 打印网站与工具箱地址，并说明这个窗口要一直开着、Control-C 停止。

它与任何对话会话无关，用户可随时自行启动。README 顶部新增「打开本地预览（最简单的方式）」一节，并指出另有完全不需要服务器的离线副本。

### 全站尾斜杠（顺带修掉，因为它直接妨碍用户自助调试）

启动器的终端日志里出现 `[404] /fr/groupe`——在预览里点导航就 404。这正是[上线前检查](../launch-readiness-2026-09-22.md) A1 记录的问题：Astro 配置是 `trailingSlash: 'always'`，站内链接却几乎都没写尾斜杠。既然用户要自己在预览里点来点去，这条不能再挂着。

- 源码 39 处链接补上尾斜杠，涉及 11 个文件；`Navigation.astro` 的品牌模板字符串和 `BrandGrid.astro` 的品牌卡链接另行手改。
- **两处刻意不动**：`routes.ts` 的 `path === '/en'` 和 `[review].astro` 的 `v.page !== '/fr/visual-plan'` 是字符串比较，不是链接。
- **配套改动**：`Navigation.astro` 原本写 `localizedPath(...).replace(/\/$/, '')`，特意剥掉尾斜杠去跟无斜杠的 href 比较。只加 href 不改这行，`aria-current` 和当前页高亮会全部失效。已改为保留尾斜杠。
- `visuals.json` 的 `page` 字段同样统一（它渲染成 dev-only 素材规划页上的链接），并同步改了 `[review].astro` 里对 `/fr/visual-plan/` 的比较。

## 证据

- 启动器冷启动实测：从端口空闲开始，脚本自动起服务、等待就绪、打开工具箱，`/fr/` 与 `/design-preview/` 均返回 200；重复运行走「已在运行」分支不重复启动。`bash -n` 语法检查通过。
- `npx tsc --noEmit` 无输出；`npm run build` 37 页、38 份内部链接、34 个双语页面全部通过。
- 构建产物扫描：修改前 `/fr/presse` 等 7 类链接共 24 处无尾斜杠，修改后为 **0**。
- 开发服务器逐一请求 12 条法英路由，全部 200（此前无斜杠形式一律 404）。
- 浏览器打开 `/fr/groupe/` 确认导航 href 全部带尾斜杠，且 `Le groupe`、`À propos` 仍正确标记 `aria-current="page"`——即配套的比较逻辑没有被改坏。
